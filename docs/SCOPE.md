# Heart & Soul Save Editor — Product Scope

A local, browser-based save editor for **Pokémon Heart & Soul v1.2.1** (pokeemerald-based GBA hack).
It edits only the `.sav` file. The ROM is never touched.

## Goals

1. **Never lose or corrupt data.** Every write is verified, the original is always backed up, and the
   editor refuses to save anything it cannot prove is consistent.
2. **Exact to this hack.** Structure offsets, item/move/species tables and formulas (stats, nature, shiny)
   come from the hack's own source and build output, not from vanilla Emerald assumptions.
3. **The basics, done very well.** A small set of editors that cover what players actually want,
   with a clean, fast UI.

## Non-goals

- Legality checking (PKHeX-style). The editor validates *structure*, not "could this exist in-game".
- Other games / hack versions out of the box. (The data pipeline is reusable: point it at another
  pokeemerald-based source tree and regenerate — see Tooling.)
- Editing the ROM, cheats, or in-emulator memory.

## Features (v1)

### File handling & safety
| Feature | Detail |
|---|---|
| Open | Pick the save folder (Chrome/Edge) or a single `.sav` file (any browser). |
| Validation on load | Every sector: signature, id, checksum. Active slot chosen with the game's own rule. Anything unexpected → read-only mode with an explanation. |
| Change review | Before saving: a list of every change (“Bag: Rare Candy 3 → 99”, “Box 2 / Slot 5: Pidgeot Lv 30 → 45”). |
| Save | Folder mode: timestamped backup in `backups/` next to the save, then write in place. File mode: download the edited file. |
| Write verification | Output is re-parsed; all checksums valid; every edit read back and compared; all bytes outside edited sectors byte-identical to the original. Any mismatch aborts the save. |
| Discard | Revert all unsaved changes. |
| Emulator warning | Reminder to close the game in mGBA before saving (a running emulator overwrites the file). |

### Trainer
- Show: name, gender, Trainer ID / Secret ID, play time, challenge & randomizer settings (read-only, for context).
- Edit: money, Game Corner coins, Battle Points.

### Bag
- All pockets: Items, Key Items, Poké Balls, TMs & HMs, Berries — plus PC item storage.
- Add / remove / change quantity, with searchable item picker (names and icons from the hack).
- Pocket rules enforced (an item can only go in its own pocket; pocket capacity; quantity limits).
- Quick actions: *Add all TMs*, *Add all HMs*, *Set quantity to max*.

### Pokémon (party + all 15 PC boxes)
- Box view with icons; party view with HP/level.
- Editor per Pokémon:
  - Species, nickname, level (EXP kept consistent), friendship, held item, Poké Ball
  - Nature (via the hack's *hidden nature* field — keeps PID, gender and shininess intact)
  - Ability slot (shows the ability name for the current save settings)
  - Shiny on/off (rerolls only the PID's upper half; gender and nature preserved)
  - Moves (searchable) with PP and PP Ups
  - IVs, EVs (with 510/252 guidance)
  - Live stat preview using the hack's exact stat formula (incl. Base Stat Equalizer / level-50 options)
- Party Pokémon: stats recalculated after edits; optional *heal* (HP / status / PP).
- Create a new Pokémon in an empty slot (player as OT, sensible defaults, optional Pokédex registration).
- Release (delete), move or swap between any party/box slots.

## Explicitly out of scope (v1)
Map position, event flags/vars, Pokédex editor, eggs, ribbons, contest stats, Pokérus, mail, daycare,
decorations/secret bases, Hall of Fame, challenge/randomizer setting changes.

## Tooling

| Area | Choice | Why |
|---|---|---|
| Language | TypeScript (strict) everywhere | One language for core, tools, tests and UI. |
| Core library | `src/core` — pure TS, no DOM, no dependencies | Reusable, unit-testable, runs in Node and browser. |
| UI | React + Vite | Fast dev loop; static build that opens offline. |
| Tests | Vitest | Unit, property (round-trip) and real-save fixture tests. |
| Game data | Extracted from the hack's **build output** (`pokemonHnS.elf`) | Exactly the tables the game uses: species, moves, items, abilities, EXP curves, icons. |
| Save layout | Generated by compiling a probe against the hack's headers with the real ARM toolchain (Docker) | Exact struct offsets and bitfield positions; no hand-copied numbers. |
| Emulator verification | mGBA's GDB stub driven from Node | Boots the real game with an edited save and checks that it loads, that RAM matches what the editor wrote, and that our stat formula matches the game's own `CalculateMonStats`. |

### Project structure
```
HnS-Save-Editor/
  docs/                 SCOPE.md, ARCHITECTURE.md
  tools/                data pipeline (layout probe, ELF extractor, sprite renderer) + emulator harness
  src/core/             save format, crypto, Pokémon, bag, trainer, validation (no UI)
  src/data/             generated JSON + sprites (committed; regenerate with `npm run gen`)
  src/ui/               React app
  tests/                unit + fixture tests; fixtures/ is git-ignored (contains real saves)
```

### Commands
| Command | What it does |
|---|---|
| `npm run dev` | Start the editor locally |
| `npm run build` | Static build into `dist/` |
| `npm test` | All unit + fixture tests |
| `npm run gen` | Regenerate layout + game data from the hack source/build |
| `npm run verify:emu -- <file.sav>` | Boot the save in mGBA and verify it loads and matches |
